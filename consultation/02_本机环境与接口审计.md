# 本机环境与接口审计

## 已验证环境

| 项目 | 当前状态 |
|---|---|
| 硬件 | Apple Silicon `arm64` |
| macOS | 当前系统高于Freeplane官方最低macOS 14要求 |
| Freeplane | 1.13.3，安装在`/Applications/Freeplane.app` |
| Freeplane Java | 捆绑OpenJDK 21 |
| Node.js | 22.17.1 |
| npm | 10.9.2 |
| Codex MCP | 支持本地STDIO和Streamable HTTP；本项目选择STDIO |
| 开发仓库 | 外置项目卷（ExFAT；咨询包中已去除本机绝对路径） |
| 依赖与测试盘 | Node依赖、缓存及临时构建放本机APFS，避免直接在ExFAT运行 |

## 已验证Freeplane自动化入口

Freeplane启动器的本机帮助输出确认：

- `-R<file>`：按路径执行脚本。
- `-X<menukey>`：执行菜单动作。
- `-S`：执行后停止。
- `-N`：设置非交互模式。
- `-U<userdir>`：指定独立用户配置目录。

安装包还包含：

- Groovy脚本和Add-on机制。
- 本地Javadoc与脚本API文档。
- `mindmapmodemenu.xml`等菜单定义。
- 批处理和脚本导出能力。

本包中的`inventory/freeplane_menu_entries.csv`与`inventory/freeplane_api_types.csv`由构建脚本直接从已安装1.13.3生成，避免手工估计。菜单存在不代表脚本API可以无界面调用；具体可用性必须逐阶段实测。

## 已验证Codex约束

- 本地Codex客户端可通过项目或用户`config.toml`连接STDIO MCP服务器。
- MCP工具应提供明确Schema、结构化结果、稳定标识与准确的只读/写入/破坏性注解。
- 工具应围绕用户目标设计，不应把大量内部动作直接暴露给模型。
- 工具调用必须用Freeplane状态回读验证实际效果。
