# v0.5 qualification

Freeplane MCP v0.5 adds one goal-level GUI tool only after bilingual isolated qualification. `freeplane_invoke_action` accepts exact enums for presentation start, stop, first, previous, next, and last, plus print-preview open and close.

The server checks the active map and expected content/view revisions before invoking a minimal ad-hoc-signed Swift Accessibility helper. The helper binds to the bridge-reported Freeplane PID, bundle ID, main window, and exact English or Simplified Chinese menu titles. The bridge then reads back presentation or preview-window state before returning `effect_status=verified`.

When another application owns the macOS global menu, dry-run selects the exact path from the authenticated bridge locale and reports `menu_resolution=deferred_until_focus`; it does not steal focus. A real invocation must focus the bound Freeplane process, resolve that exact localized item, and pass state readback.

The helper never accepts a raw action key, caller-supplied menu path, AX query, script, shell command, or screen coordinate. It never presses the final Print button. Destructive modal imports, node/map encryption, preferences, final printing, and other unqualified modal workflows remain unavailable.

Build the helper and run the gate with:

```bash
npm run build:helper
npm run qualify:v0.5
```

The build command prints the cache path of the helper, and the qualifier injects that path automatically. An ordinary development server must receive that absolute path through `FREEPLANE_MCP_AX_HELPER`; the v1.0 installed launcher configures its managed helper automatically. Otherwise the GUI route reports unavailable. The GUI route also requires macOS Accessibility permission for the signed helper. Read-only, edit, organization, lifecycle, export, and closed-file routes retain their earlier qualification and do not require Accessibility.

The authoritative evidence is `qualification/reports/v0.5-local.json`: 30 checks cover the exact twelve-tool surface, helper signature, bilingual menu resolution, focus recovery, all six presentation transitions, idempotent replay, preview open/cancel, stale-revision and arbitrary-input rejection, zero map-content mutation, private logs, explicit capability cuts, and preservation of pre-existing Freeplane processes.
